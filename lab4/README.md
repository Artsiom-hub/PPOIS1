# Лабораторная работа №4

## Тема

Разработка веб-интерфейса к программной системе лабораторной работы №1.

## Цель работы

Цель лабораторной работы — разработать клиент-серверное веб-приложение к программной системе издательства, реализованной в лабораторной работе №1, а также выделить общий код, используемый как консольным интерфейсом, так и веб-интерфейсом.

## Постановка задачи

В рамках лабораторной работы необходимо:

1. Использовать фреймворк для создания веб-приложений.
2. Реализовать пользовательский веб-интерфейс.
3. Обеспечить управление моделью из лабораторной работы №1 через веб-страницу.
4. Обеспечить отображение текущего состояния модели.
5. Выделить общий код для CLI и веб-интерфейса.
6. Продемонстрировать работоспособность CLI и веб-интерфейса с выделенным общим кодом.
7. Задокументировать реализацию при помощи языка разметки Markdown.

В качестве фреймворка для разработки веб-приложения используется `Flask`.

- обработка HTML-форм;
- загрузка состояния модели;

Основные операции, реализованные в `app.py`:

- добавление автора;
- добавление редактора;
- подача статьи;
- рецензирование статьи;
- подготовка статьи к публикации;
- добавление журнала;
- добавление статьи в журнал;
- печать журнала;
- выпуск электронной версии;
- распространение выпуска.

## `cli.py`

Файл `cli.py` содержит консольный интерфейс программы.

Он используется для демонстрации того, что консольная версия и веб-версия работают с одним и тем же общим кодом.

Через `cli.py` можно выполнить следующие действия:

- добавить автора;
- добавить редактора;
- подать статью;
- рецензировать статью;
- выполнить вёрстку статьи;
- добавить журнал;
- добавить статью в журнал;
- напечатать журнал;
- выпустить электронную версию;
- распространить выпуск;
- посмотреть текущее состояние модели.

CLI не содержит собственной бизнес-логики. Он только принимает данные от пользователя и вызывает классы и сервисы из модуля `core`.

---

## `core/`

Каталог `core` содержит общий код программной системы.

Этот модуль используется одновременно:

- консольным интерфейсом `cli.py`;
- веб-интерфейсом `app.py`.

В `core` вынесены:

- классы предметной области;
- сервисы бизнес-логики;
- интерфейсы;
- пользовательские исключения;
- механизм сохранения и загрузки состояния.

Выделение `core` позволяет избежать дублирования кода между CLI и веб-приложением.

---

## `core/classes/`

Каталог `core/classes` содержит классы предметной области.

Основные классы:

| Класс | Назначение |
|---|---|
| `Author` | Описывает автора научной статьи |
| `Editor` | Описывает редактора, выполняющего рецензирование |
| `ScientificArticle` | Описывает научную статью |
| `Journal` | Описывает научный журнал |
| `PublishingHouse` | Описывает издательство |
| `PrintedEdition` | Описывает печатный выпуск |
| `ElectronicVersion` | Описывает электронную версию выпуска |

---

## `core/services.py`

Файл `services.py` содержит сервисы, реализующие основную бизнес-логику системы.

Основные сервисы:

| Сервис | Назначение |
|---|---|
| `ArticleSubmissionService` | Подача статьи |
| `PeerReviewService` | Рецензирование статьи |
| `LayoutServiceImpl` | Подготовка статьи к публикации |
| `PrintService` | Печать журнала |
| `ElectronicPublishingService` | Выпуск электронной версии |
| `DistributionServiceImpl` | Распространение выпуска |

Сервисы используются как в `cli.py`, так и в `app.py`.

---

## `core/interface.py`

Файл `interface.py` содержит интерфейсы сервисов.

Интерфейсы используются для описания общего поведения сервисов и отделения абстракций от конкретных реализаций.

---

## `core/exceptions.py`

Файл `exceptions.py` содержит пользовательские исключения.

Примеры исключений:

- `AuthorNotFoundError` — автор не найден;
- `EditorNotFoundError` — редактор не найден;
- `ArticleNotFoundError` — статья не найдена;
- `JournalNotFoundError` — журнал не найден;
- `InvalidInputError` — введены некорректные данные.

---

## `core/storage.py`

Файл `storage.py` отвечает за сохранение и загрузку состояния модели.

Состояние хранится в файле:

```text
data/state.json
```

Файл содержит данные:

- об авторах;
- о редакторах;
- о статьях;
- о журналах;
- об издательстве.

Один и тот же файл состояния используется консольным интерфейсом и веб-интерфейсом.

---

## `templates/index.html`

Файл `index.html` содержит HTML-шаблон главной страницы веб-приложения.

На странице размещены:

- формы для управления моделью;
- таблица авторов;
- таблица редакторов;
- таблица статей;
- таблица журналов;
- блок с текущим состоянием издательства;

Шаблон обрабатывается Flask через механизм `render_template`.

## `static/styles.css`

Файл `styles.css` содержит стили веб-интерфейса.

В нём описано оформление:

## `data/state.json`

# Работа с состоянием модели

Состояние модели сохраняется в JSON-файле:

```text
data/state.json
```

При запуске CLI или веб-приложения состояние загружается из этого файла.

После выполнения операций состояние сохраняется обратно в файл.

Пример структуры `state.json`:

```json
{
    "authors": {},
    "editors": {},
    "articles": {},
    "journals": {},
    "publisher": {
        "name": "International Science Publisher",
        "journals": []
    }
}
```

Если файл состояния отсутствует, программа создаёт пустое состояние модели.

Если издательство ещё не создано, оно создаётся автоматически с названием:

```text
International Science Publisher
```

# Жизненный цикл статьи

Статья проходит несколько состояний.

Начальное состояние статьи:

```text
submitted
```

После рецензирования статья получает статус:

```text
reviewed
```

После подготовки к публикации статья получает статус:

```text
layout_ready
```

Схема изменения состояния:

```text
submitted -> reviewed -> layout_ready
```

Статус статьи отображается в веб-интерфейсе в таблице статей.

# Обработка ошибок

В системе предусмотрена обработка ошибочных ситуаций.

Примеры ошибок:

- попытка добавить автора с уже существующим ID;
- попытка добавить редактора с уже существующим ID;
- попытка подать статью без существующего автора;
- попытка рецензировать несуществующую статью;
- попытка выполнить вёрстку несуществующей статьи;
- попытка добавить статью в несуществующий журнал;
- попытка добавить журнал с уже существующим ID;
- ввод текстового значения вместо числового ID.

В CLI ошибки выводятся в терминал.

В веб-интерфейсе ошибки отображаются на странице через flash-сообщения Flask.

# Особенности реализации веб-интерфейса

Веб-интерфейс реализован как серверное приложение на Flask.

Все формы находятся на странице:

```text
templates/index.html
```

После отправки формы Flask выполняет соответствующее действие, сохраняет состояние модели и перенаправляет пользователя обратно на главную страницу.

Для передачи данных из Python в HTML используется шаблонизатор `Jinja2`.

Пример вывода списка авторов:

```html
{% for author_id, author in authors.items() %}
    <tr>
        <td>{{ author_id }}</td>
        <td>{{ author.name }}</td>
        <td>{{ author.affiliation }}</td>
        <td>{{ author.email }}</td>
    </tr>
{% endfor %}
```

# Вывод

В ходе выполнения лабораторной работы был разработан веб-интерфейс к программной системе издательства. Для реализации клиент-серверного приложения был использован фреймворк Flask.

Код предметной области, сервисы, интерфейсы, исключения и механизм хранения состояния были вынесены в общий модуль `core`.

Благодаря этому консольный интерфейс и веб-интерфейс работают с одной моделью и используют одну бизнес-логику.

Реализация удовлетворяет требованиям задания: веб-интерфейс предоставляет возможности управления моделью, отображает текущее состояние системы, использует общий код с CLI и сохраняет состояние между запусками программы.
